MODIFICATION DOCUMENTATION: FIRST MODEL: FACTOR: SPECIFICITY
============================================================
Every problem found in the specificity model and how it was fixed, in the
order it happened, from the very first version to version 4.

Files (all in journal/):
  first_model_factor_specificity.py       the model
  test_first_model_factor_specificity.py  hand-solvable tests + search checks
  cdc_reference_check.py                  CDC panel on the real reference genome
  test_cases_specificity.txt              every test case and its outcome


-----------------------------------------------------------------------------
VERSION 1  -  first working model                       commit 8e3f1c3, 2026-10-29
-----------------------------------------------------------------------------
Built: a specificity-only model (no melting temperature, no real data).
  - k-mer index of the target so primers are not compared at every position
  - binding sites on both strands, with a user-set mismatch allowance
  - mismatches reported by distance from the 3' end
  - "+" and "-" sites facing each other paired into products
  - 7 hand-solvable cases on fake primers and a fake target (exact match,
    reverse strand, 3'/5' mismatches, multiple products, primers facing
    away, no site)

1. Problem: the mismatch allowance was hard to find in the code.
   Fix:     a starred "USER SETTING: MISMATCH ALLOWANCE" banner above it.


-----------------------------------------------------------------------------
VERSION 2  -  bad sequencing data                       commit 81d909e, 2026-10-29
-----------------------------------------------------------------------------
Question raised: does the model need read alignment (Salmon, STAR, TopHat) or
handling for degraded ends?
Answer: no read alignment is needed; the genomes are finished NCBI consensus
sequences. But poor sequencing still leaves traces in them: N bases and
missing ends. GC content was considered as a quality signal and rejected
(FASTA has no quality scores; SARS-CoV-2 has real AT-rich regions).

2. Problem: an N in the genome was counted as a mismatch, so missing data
   looked like a mutation and a primer could be wrongly reported as lost.
   Fix:     unknown bases are tracked separately and never count as
            mismatches. Every primer gets one of three outcomes: binds,
            mismatched, or not assessable.

3. Problem: primer sites that ran off the start or end of a sequence were
   never found at all.
   Fix:     placements hanging off either end are checked; they are reported
            as "not assessable" with the reason "runs off the start/end".

4. Problem (found while fixing 2): a long run of Ns would make every primer
   "not assessable".
   Fix:     a not-assessable site needs at least 10 known bases that agree
            with the primer (MIN_KNOWN_BASES).

New tests: Cases 7-10 (Ns in a site, cut end, cut start, real mismatches
next to missing data).

VERSION 3  -  review of version 2                       commit fcf677c, 2026-10-30
-----------------------------------------------------------------------------
Problems identified in a review of version 2, then fixed:

7. Problem: logic bug. In Case 10 the reverse primer could not bind anywhere,
   yet the assay was "not assessable" only because of an N in the forward
   site. No product was possible, so the answer should be "no product".
   Fix:     the model pairs every site that might bind (including not
            assessable ones) and says "not assessable" only when missing data
            could actually create a product.

8. Problem: a mismatch at the 3' end counted the same as one at the 5' end,
   although 3' mismatches are the ones that stop extension.
   Fix:     sites and products with a mismatch within 3 bases of the 3' end
            are flagged "3' at risk", with a warning (3' END RISK WINDOW
            banner).

9. Problem: the qPCR probe was ignored; a product gives no signal unless the
   probe binds inside it.
   Fix:     optional probe. Primers binding without the probe give a new
            assay outcome: "no signal".

10. Problem: degenerate primer bases (e.g. the Y in the CDC N3 probe) were
    treated as mismatches and could not be searched.
    Fix:     IUPAC codes in primers accepted (Y = C or T, etc.).

11. Problem: insertions and deletions were not recognised (e.g. Alpha's
    spike 69-70 deletion would look like many mismatches).
    Fix:     for a failed primer, a near-miss search finds the closest site
             allowing one insertion or deletion, counted as one event.

12. Problem: mismatches gave only a position, not the base change, so the
    model could not say which mutation was responsible.
    Fix:     every mismatch reported as "primer C, genome G".

13. Problem: a failed primer gave no clue where it almost bound.
    Fix:     near-miss report for every mismatched primer, or "none close".

14. Problem: positions were 0-based, unlike the CDC table and genome browsers.
    Fix:     positions printed 1-based.

15. Problem: untested edge cases.
    Fix:     Cases 11-19 (primer pairs with itself, overlapping sites,
             allowance too high, palindromic primer, degenerate base, probe
             binds / fails, insertion, deletion).

Problems found while building version 3:

16. Problem: the near-miss search starts from exact 5-base stretches, so in
    Case 10 (3 mismatches spaced 4 bases apart) it found nothing.
    Fix:     documented as a known limit; Case 10 now expects "none close".

17. Problem: on a random 30,000-base sequence the near-miss search reported a
    fake "6-base deletion + 1 mismatch" for a CDC primer: pure coincidence.
    Fix:     a near-miss needs at least 14 primer bases matching exactly
             (MIN_MATCHED_BASES).

18. Problem: coincidences still appeared (a deletion plus 2-3 mismatches),
    because a gap can sit in many places.
    Fix:     a near-miss with an insertion/deletion may have at most 1 other
             mismatch. Result: 0 false near-misses on 10 random genomes,
             while a real 6-base deletion in a 20-base primer is still found.
             Consequence: a 16-base primer can only show deletions of up to
             2 bases, so Case 18 changed from a 4-base to a 2-base deletion
             and Case 18b (6-base deletion refused) was added.

VERSION 4  -  review of version 3                       committed 2026-10-30
-----------------------------------------------------------------------------
Problems identified in a review of version 3, then fixed:

19. Problem: "not assessable" was too cautious. A site with 0 mismatches and
    1 N, with 2 mismatches allowed, binds even if the N is a mismatch, but
    the model still said "not assessable".
    Fix:     if mismatches + unknown bases still fit the allowance, the site
             "binds" ("binds even if every unknown base is a mismatch").
             Case 7b added; in Case 10 the forward primer now binds.

20. Problem: ambiguity codes in the genome were thrown away. Genome R (A or G)
    can never match a primer C, but was treated like N.
    Fix:     each genome letter is a certain match, a certain mismatch, or
             unknown, depending on what it could be. Case 20 added.

21. Problem: mismatches were all-or-nothing; a mild G-T mismatch counted the
    same as a severe C-C one.
    Fix:     every mismatch is graded severe (primer-template A-A, G-A, A-G,
             C-C) or mild (all others), after Stadhouders et al. 2010 and
             Kwok et al. 1990. The 3' risk is graded high / low / possible.
             The allowance still counts each mismatch as 1, so the search
             guarantee holds. Case 3b updated, Case 21 added.

22. Problem: any insertion or deletion meant failure, though a 1-base gap
    near the 5' end usually still lets a primer extend.
    Fix:     a site with one 1-base gap in the primer's 5' half binds, the
             gap counting as 1 mismatch. Gaps in the 3' half still fail and
             are explained by the near-miss search. Case 22 added.

23. Problem: the model had never been run on real data.
    Fix:     cdc_reference_check.py runs CDC N1, N2, N3 (with probes) and
             the RNase P negative control on NC_045512.2. Each N assay gives
             exactly one product at the verified positions, every probe
             binds (including N3's degenerate probe), and RP gives none.

24. Problem: nothing proved the fast k-mer search finds every site.
    Fix:     Case 23 compares it with a slow every-position search on 200
             random targets x 3 allowances: identical on all 600.

25. Problem: the random-genome check from item 18 was only run by hand.
    Fix:     saved as Case 24.

26. Problem: the model and its tests shared one ~1,000-line file.
    Fix:     split into the model file and test_first_model_factor_specificity.py;
             a FASTA reader was added to the model for real genomes.

Problems found while building version 4:

27. Problem: the CDC check reports N1 as 72 bp, but the primer table lists
    73 bp. The table's own published (28303-28374) and verified
    (28287-28358) coordinates both span 72 bases, so the model is
    consistent with the coordinates.
    Status:  OPEN. The check is left as a FAIL; the 73 bp value in the table
             should be checked against Lu et al. (2020) before changing it.

28. Problem: reports read "deletion of 1 bases (primer bases 15-15 ...)".
    Fix:     now "deletion of 1 base (primer base 15 from 3' ...)".


-----------------------------------------------------------------------------
STILL OPEN (known limits after version 4)
-----------------------------------------------------------------------------
  - N1 amplicon size: 72 bp computed vs 73 bp in the table (item 27).
  - The near-miss and small-gap searches need an exact 5-base stretch.
  - The near-miss rules (14 matching bases, event limits) were tuned on
    random sequence, not real genomes with repeats.
  - Severity uses a two-level rule; real mismatch effects also depend on
    neighbouring bases and position beyond the 3' window.
  - Sites running off the start print negative positions (e.g. -3-48).
  - Input is not cleaned of pasted spaces or line breaks.
  - The k-mer index is rebuilt on every run; the test suite takes ~14 s.
  - The mismatch allowance can only be changed in the code.
  - Not yet run on the Alpha, Delta and Omicron genomes.
